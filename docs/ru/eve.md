# Сборка и публикация eve

Исходники eve лежат в `eve/`: копия [vercel/eve](https://github.com/vercel/eve)
на коммите `eb5949a622801b35a2a6f78bb58d9eef27273cac` (eve 0.51.1).
В ней пакет eve, зависимость catalog, документация пакета и входы сборки.
Правки Ивы — обычные коммиты в этом каталоге; их держат тесты границы Ивы.
Переход на новый коммит upstream — отдельное решение по ADR-0023.

Правьте `eve/packages/eve/src/`, прогоняйте затронутые тесты upstream и тесты
границы Ивы, затем коммитьте исходники. Мейнтейнер использует Node ≥24 и pnpm
11.25.0. Для нового архива задайте свежий номер `0.51.1-iva.N` в
`scripts/build-eve.sh` и `scripts/eve-release.sh`. Пользователь получает готовый
пакет eve и собирает только агента Ивы.

Из чистого дерева:

```sh
bash scripts/eve-release.sh
```

Команда вызывает `scripts/build-eve.sh`, сохраняет архив в игнорируемый
`.eve-out/release/`, считает SHA-512 SRI и записывает URL, версию и integrity в
`package.json` и `package-lock.json`. Повторный запуск использует тот же архив,
сверив хеши исходников и пакета. Новым исходникам нужен новый номер N.
Для сравнения сборок: `bash scripts/build-eve.sh <пустой-каталог>`.

Порядок публикации:

1. Собрать из закоммиченных исходников и закоммитить файлы зависимости локально.
2. Создать метку `eve-0.51.1-iva.N` на этом коммите и отправить метку.
3. Создать выпуск GitHub в `smixs/iva-agent` и загрузить соответствующий архив.
4. Скачать архив по итоговому URL зависимости и сверить SHA-512 SRI с lockfile.
   Команда подсчёта приведена на [английской странице](../eve.md).
5. Выполнить `npm ci` в чистом дереве по итоговой ссылке, затем
   `node --test scripts/eve-copy.test.ts` и тесты границы.
6. Отправить коммит в `beta` после успешных проверок.

Опубликованные метки `eve-*`, имена вложений и байты архивов постоянны.
Исправление получает новый N: старые версии Ивы используют прежние URL.
Архивы хранятся вне git.

В `node_modules/eve/BUILD.json` лежат коммит upstream, версии пакета и
инструментов, `sourceTreeHash` и `packedTreeHash`. Тест `scripts/eve-copy.test.ts`
сверяет исходники, установленный пакет и lockfile. Зависящий от пути машины
`.vendor-stamp.json` исключён из хеша пакета.

# Кнопки живут внутри сообщения, а не под ним

Bot API 24.08.2026 добавил в rich message кнопки (`RichMessageButton`, `<tg-button>`):
кнопка стала inline-элементом текста, стоит в строке рядом с пояснением, стили
`danger`/`success`/`link`, нажатие приходит тем же `callback_query`. До этого все меню,
мастера, предложение обновления и «Работаю» с ⏹ рисовались inline-клавиатурой под
сообщением: ряд коротких слов без места для пояснения.

**Решение (13.09.2026, слово владельца).** Всякая кнопка Iva — часть rich message.
Экран меню или мастера возвращает одну markdown-строку: заголовок, абзацы «кнопка — что
она делает», таблицы там, где данные табличные; ряд `<tg-button-row>` только для
равноправных вариантов без пояснений (да/нет, список моделей, ответы квиза). Один
помощник синтаксиса — `scripts/lib/telegram-buttons.ts`; `agent/` держит свою пятистрочную
копию (граница слоёв). Модель предлагает кнопки сама по скиллу `telegram-buttons`, кладя
в `callback_data` саму реплику пользователя; Bridge превращает такой тап в обычное
входящее сообщение с этим текстом, тем же путём, что и любой текст (allowlist, очередь,
inbound pipeline). Пространства `iva_*` и `eve*` по-прежнему обрабатываются кодом.

Один рендер, без запасного пути: отказ Bot API — ошибка в журнале, как у любой отправки.
Клиентам старше августа 2026 кнопок не видно; это цена, названная в CHANGELOG.

**Отвергнуто.** Двойной рендер «rich или inline по результату первого вызова» — вторая
delivery-подсистема (philosophy §5) и два места, которые разойдутся. Протокол команд в
`callback_data` для кнопок модели — второй `handleWizardCallback`, а модель и так пишет
реплику. Стриминг черновика с родным Stop — отдельное решение, не про кнопки.

**Точка удаления.** Когда Bot API даст подпись кнопки в `callback_query`, из скилла уходит
ограничение 64 байта на `callback_data`.
